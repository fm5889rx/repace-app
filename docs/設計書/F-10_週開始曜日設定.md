# F-10 週開始曜日設定 — 機能設計書

> 共通事項は [設計書](../設計書.md) を参照。

| 項目 | 内容 |
| :--- | :--- |
| 機能ID / 優先度 | F-10 / 優先 |
| 画面 | W-04 設定画面（`/settings`） |
| API | S-01 `PATCH /api/v1/user/settings`、A-04 `GET /api/v1/user` |
| テーブル | users（R/U：`week_start_day`） |

## 1. 概要

週の開始曜日は人によって異なる（土曜、月曜、日曜（カレンダーと同じ）など）。設定画面で **カレンダーから「週の開始日」を選ぶと、その日の曜日が開始曜日として自動的に設定される**。たとえば 10/17（土）を選ぶと、毎週土曜日が週の始まりになる。既定は土曜（原紙の書式に合わせる）。

- 選んだ日付そのものは保存しない。保存するのは、そこから決まる曜日（`week_start_day`）だけである。
- 曜日を直接選ぶ欄は設けない（カレンダーで選ぶ方式に一本化する）。
- **保存するとき、サーバーはデータベースの直近の記録を検索し、新しい週の区切りと合わない（日付が重複する、または欠ける日が出る）場合は設定エラーを返して、変更を保存しない。** 記録がまだない場合と、現在と同じ曜日を選んだ場合は、常に保存できる（詳細は 4 章）。

## 2. 画面（W-04）

| 項目 | 種別 | 入力チェック |
| :--- | :--- | :--- |
| 週の開始日 | カレンダー（日付の選択） | 必須、有効な日付、2000-01-01〜2100-12-31 |

- 現在の設定を「現在: 毎週土曜日が週の始まりです」の形式で表示する。
- カレンダーで日付を選ぶと、画面に即時にプレビューを出す（サーバーには送らない）。
  - 「選んだ日: 2026/10/17（土）→ 毎週土曜日が週の始まりになります」
  - 「この場合の1週間: 10/17（土）〜10/23（金）」
- 操作: 「保存」ボタン、W-03 への戻りリンク、ログアウトボタン。
- 保存に成功したら「保存しました」を表示し、W-03 に戻ると新しい週区切りで表示される。
- 整合性エラーのときは、保存せず、カレンダーの下に設定エラーを表示する（内容は 3 章）。選んだ日付はそのまま残す。
- 注意書き: 「記録がある場合、週の始まりの曜日は変更できません。現在と同じ曜日を選んでください」と示す。
- カレンダーの初期表示は、今日を含む月とし、現在の開始曜日の日を目印にする。

## 3. API

**S-01 週開始曜日の設定** `PATCH /api/v1/user/settings`（認証必要、CSRF 必須）

```json
// 入力（カレンダーで選んだ日付）
{ "week_start_date": "2026-10-17" }
// 出力 200（日付の曜日から決まった開始曜日。0=日〜6=土）
{ "data": { "week_start_day": 6 } }
```

| 検証 | 内容 |
| :--- | :--- |
| `week_start_date` | 必須、`YYYY-MM-DD` として存在する日付、2000-01-01〜2100-12-31 |

| ステータス | 条件 |
| :--- | :--- |
| 401 | 未ログイン |
| 419 | CSRF トークン不一致 |
| 422 | 日付が空、形式が不正、存在しない日付（例 2026-02-30）、範囲外 |
| 422 | 週の区切りの整合性エラー（日付の重複・欠損。下記） |

**整合性エラーの応答**（422）

```json
{
  "message": "直近の記録の週（10/17〜10/23）と、新しい週の区切りが合いません。この設定にすると、日付が重複するか、欠ける日が出ます。",
  "errors": { "week_start_date": ["直近の記録の週（10/17〜10/23）と、新しい週の区切りが合いません。この設定にすると、日付が重複するか、欠ける日が出ます。"] },
  "code": "week_start_conflict",
  "details": {
    "latest_week": { "start": "2026-10-17", "end": "2026-10-23" },
    "missing_days": 2,
    "overlap_days": 5
  }
}
```

- 画面の表示文言: 「直近の記録（10/17〜10/23の週）と週の区切りが合いません。この設定にすると、2日が欠けるか、5日が重複します。記録がある場合、週の始まりは現在と同じ曜日（土曜）にしてください。」

## 4. データ

- `users.week_start_day`（tinyint unsigned、既定 6=土）を、`week_start_date` の曜日（0=日〜6=土）に更新する。ただし、先に下の「整合性の検査」を行い、エラーなら更新しない。
- 週の開始日の求め方（R-01・R-04 で共通）: `開始日 = 日付 − ((その日の曜日 − week_start_day + 7) % 7)` 日。曜日は 0=日〜6=土。
**整合性の検査（週の区切りが変わっても、日付の重複・欠損が出ないことの確認）**

1. データベースで、この利用者の**直近の記録**を検索する。`daily_summaries.record_date`・`activity_segments.record_date` の最大値と、`weeks.start_date` の最大値＋6日（週の最終日）のうち、最も新しい日を **L** とする。いずれの表にも記録がなければ、検査せずに保存する。
2. 現在の設定（`week_start_day`）で L を含む週 `[cs, ce]`（`ce = cs + 6`）を求める。
3. 新しい開始曜日の週が、この週の直後（`ce + 1`）から続くかを調べる。`g = (新しい開始曜日 − (ce + 1) の曜日 + 7) % 7`。
   - `g = 0`（現在と同じ曜日）: 週が連続し、重複も欠損もない。保存できる。
   - `g ≠ 0`: 新しい週が `ce + 1` からずれる。**`g` 日が欠ける（どの週にも属さない）か、`7 − g` 日が重複する（2つの週に属する）。** 設定エラー（`week_start_conflict`）を返す。
4. エラー応答の `details.missing_days` に `g`、`overlap_days` に `7 − g` を入れる。

- 検索は3つの最大値の取得のみ（いずれも利用者と日付の索引を使う）。
- この方式により、記録がある利用者は週の始まりの曜日を変えられない。変えたい場合は、記録を削除して（R-06）から設定する。記録のない新規の利用者は、最初に自由に決められる（既定は土曜）。
- 既存の `weeks`（目標・所感）は、常に現在の週の区切りと一致する（ずれた週が作られない）。

## 5. 振る舞い

- 曜日の決定は、サーバーが日付の曜日から行う（画面のプレビューと一致させるため、フロントも同じ計算でプレビューする）。
- 整合性の検査は、サーバー側で必ず行う（フロントのプレビューでは記録の有無が分からないため）。
- 保存したら、画面の利用者情報（A-04 の内容）を更新し、W-03 の表示範囲とグラフの軸が変わる。
- 失敗した場合は、選択した日付を保持してエラーを表示する。

## 6. 受け入れ条件とテスト観点

| 受け入れ条件 | 観点 |
| :--- | :--- |
| カレンダーで日付を選ぶと、その日の曜日が開始曜日として設定される | 正常: 2026-10-17（土）→ 6、2026-10-18（日）→ 0、2026-10-19（月）→ 1 |
| 選んだ日付のプレビューに、曜日と1週間の範囲が出る | 手動確認 |
| 設定が再ログイン後も保持される | 正常: A-04 で `week_start_day` が保存値 |
| W-03 の週の区切りとグラフの軸が、設定した曜日に変わる | 正常: 土曜→月曜 |
| 不正な日付は拒否される | 異常: 空、`abc`、2026-02-30、1999-12-31、2101-01-01 |
| 境界の日付が通る | 境界: 2000-01-01、2100-12-31 |
| 保存に失敗しても入力データが変わらない | 正常: エラー時、行動の区間・サマリー・週の目標が変更前と同じ |
| 週の開始日の計算が正しい | 自動: 各曜日の日付と 7 通りの `week_start_day` の組み合わせ |
| 記録がない利用者は、どの曜日にも変更できる | 正常: 記録なしで 6→1 が保存される |
| 記録がある利用者が現在と同じ曜日を選ぶと保存できる | 正常: 6→6（別の週の土曜を選んでも可） |
| 記録がある利用者が別の曜日を選ぶと、設定エラーが出て保存されない | 異常: 土曜始まりで 10/23 まで記録があり月曜を選ぶ → 422 `week_start_conflict`、`week_start_day` は変わらない |
| エラーの内容に、直近の週と、欠ける日数・重複する日数が含まれる | 正常: `latest_week` が 10/17〜10/23、`missing_days` と `overlap_days` の合計が7（`g` と `7−g`） |
| 直近の記録は、日次サマリー・行動の区間・週の目標のどれから見ても検査される | 境界: 3つの表それぞれにだけ記録がある場合、未来の日付の記録がある場合 |
| 記録を削除（R-06）すると、再び曜日を変更できる | 正常: 全記録を削除してから変更 |
| 他人の記録は検査に影響しない | 異常: 他の利用者に記録があっても、自分に記録がなければ変更できる |
