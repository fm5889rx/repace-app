# ユーザー評価計画書

RePace（週間行動＆気分記録アプリ）の初期バージョンについて、実際に使ってもらい、何を・誰が・どの順で確認するかを定める計画書です。

- 要件の全体像は [要件定義書](要件定義書.md)、機能ごとの仕様は [設計書](設計書.md)・[docs/design/](design/) を参照
- 確認すべき仕様の抜け漏れは [仕様チェックリスト](仕様チェックリスト.md) で管理（実機確認の項目は Q-50 など）

> [!NOTE]
> このリポジトリは一般公開されます。評価者の氏名・病名・診療科などの個人が特定できる情報や機微な情報は、この計画書にも評価結果にも記載しません。評価者は「評価者A」「評価者B」と表記します。

## 1. 評価の目的

| # | 目的 | 確かめること |
| --- | --- | --- |
| 1 | **実用性の検証** | 医療機関などに提示するツールとして、出力した A4 横向き PDF をそのまま使えるか |
| 2 | **UI/UX の検証** | 心身の負荷が高い状態でも、ストレスなく入力できるか |
| 3 | **コア価値の検証** | 睡眠時間の日またぎ集計と PDF 出力が、生活リズムの把握・改善に役立つか |

## 2. 評価者の定義

| 評価者 | 属性 | 検証の主眼 |
| --- | --- | --- |
| **評価者A：開発者兼専門家** | 生活記録票の構造と目的、現場での活用意図を深く理解している | データの正確性、日またぎ睡眠の集計ロジックの妥当性、PDF フォーマットの完成度 |
| **評価者B：アーリーアダプター** | 生活記録表を使った体調管理を実際に必要としている当事者。アプリの利用は初めて | 直感的な使いやすさ（認知負荷の低さ）、継続して使えるか、PDF を出力するまでの導線のスムーズさ |

評価者Aは「正しく作れているか」を、評価者Bは「無理なく使い続けられるか」を見ます。見る観点を分けることで、互いの見落としを補います。

## 3. 評価フェーズと手順

```mermaid
flowchart LR
    P1["1. 環境準備"] --> P2["2. 試用期間<br>（数日〜1週間）"]
    P2 --> P3["3. PDF 出力の確認"]
    P3 --> P4["4. ヒアリング"]
    P4 --> P5["5. 結果の整理と反映"]
```

| フェーズ | 内容 | 主な担当 |
| --- | --- | --- |
| 1. 環境準備 | 開発機（iMac M4）の確認から、評価者の実機（PC・スマホ）への展開に進める。公開 URL にアクセスできること、登録・ログインができること、スマホで W-06 が表示されることを確認する。実機でしか確かめられない点（スワイプやドラムロールの操作感、iPhone の印刷・PDF 保存）は、チェックリスト Q-50 で確認する | 開発者 |
| 2. 試用期間 | 数日〜1週間、評価者が普段の生活の中で記録をつける。評価者Aは、日またぎの睡眠や重なる行動など、集計の境界になる入力も意図的に試す。評価者Bは、特別な指示をせず、ふだんどおりに使ってもらう | 評価者A・B |
| 3. PDF 出力の確認 | 試用した週を確定し、W-05 のプレビューから PDF を出力する。紙の生活記録表と並べて、見た目と内容を確かめる | 評価者A・B |
| 4. ヒアリング | 試用後に、4 の評価シートに沿って感想を聞く。評価者Bには口頭の雑談形式で行う | 開発者 |
| 5. 結果の整理と反映 | 指摘を分類し、5 の優先順位で対応する | 開発者 |

> [!TIP]
> 試用期間中は、評価者Bに「毎日入力しなければ」という負担をかけないようにします。入力できなかった日も、継続性を見るための大切な材料です。

## 4. 評価シート（チェック・アンケート項目）

### 4.1 評価者A（専門家視点）

チェックボックス形式で確認します。

**日またぎ睡眠の集計**

- [ ] 就寝が日をまたぐ入力（例: 23:00〜翌 07:00）で、睡眠時間が起きた日に計上されている
- [ ] 週をまたぐ睡眠（週の最終日の夜〜翌週の朝）でも、合計が正しい
- [ ] 睡眠が重なって入力されたとき、重なった時間が二重に数えられていない
- [ ] 24:00 の扱い（終了時刻 24:00 と翌日 0:00）で、時間が狂わない

**PDF のレイアウトの信頼性**

- [ ] A4 横向き 1 ページに収まり、2 ページ以上にならない
- [ ] 24 時間の時間軸、行動の帯、気分・疲労感のグラフが、紙の原紙と同じ構成で読める
- [ ] 重なった行動が、重なった時間だけ上下 2 段に分かれて表示される
- [ ] 食事欄・日記欄の文字が多いときも、切れずに 1 ページに収まる
- [ ] 睡眠／排便の欄で、睡眠時間が左上に表示される
- [ ] 提出する資料として、そのまま使える見た目である

**マルチデバイス対応**

- [ ] PC（W-03）で 1 週間が 1 画面に収まり、入力できる
- [ ] スマホ（W-06）で 1 日 1 画面になり、入力できる
- [ ] スマホで、週・日の切り替え（スワイプ・矢印）が使える
- [ ] 同じアカウントで PC とスマホを行き来しても、入力した内容が一致する
- [ ] iPhone と Android の両方で、PDF を出力・保存できる

### 4.2 評価者B（ユーザー視点）

> [!IMPORTANT]
> 評価者Bには、アンケート用紙を渡さず、**口頭の雑談ベース**で次の 4 点を聞きます。回答を求めすぎず、ふだんの会話の中で自然に感想を引き出します。メモは開発者が取ります。

| # | 聞くこと | 見たい点 |
| --- | --- | --- |
| 1 | **操作感**：入力するとき、負担になるところはありませんでしたか。しんどい日でも続けられそうですか | 認知負荷の低さ、継続性 |
| 2 | **睡眠の集計**：画面に出た睡眠時間は、ご自身の感覚と合っていましたか。ズレを感じた日はありましたか | 集計と体感のズレ |
| 3 | **PDF の実用性**：出力した PDF を、実際に診察などで見せられそうだと思いますか。足りないところはありますか | 出力の導線、提出物としての実用性 |
| 4 | **ネーミング**：アプリの名前として「RePace Log」と「Re:Pace」を聞いたとき、どちらがしっくりきますか。印象を教えてください | 名前の響き |

## 5. フィードバックの反映と NEXT バージョンへの展望

### 5.1 初期バージョンでの反映の優先順位

| 優先度 | 内容 |
| --- | --- |
| 最優先 | コア機能の不具合（睡眠の集計、保存、週の確定、PDF 出力の崩れ）の修正 |
| 高 | 視認性の修正（文字の大きさ、色のコントラスト、ボタンの押しやすさ） |
| 中 | 入力の手間を減らす改善（初期値、クイックタグの並びなど） |
| 低 | 見た目の好みや、新機能の要望（NEXT バージョンの検討材料にする） |

評価の結果は、仕様チェックリストの該当項目と、必要に応じて要件定義書の更新履歴に反映し、リポジトリの完成度を高めます。

### 5.2 将来的な展望（NEXT バージョン）

本リポジトリのベースが完成したあと、**商用化（マネタイズ対応）** に向けて、リポジトリをクローンして改造します。Stripe 決済や有料プランの制限は、この改造版に組み込みます。

- 今回のリポジトリ（ファーストバージョン）には、決済に関する機能を実装しない
- 改造版では、アーリーアダプターの口コミ評価を土台にして、さらにブラッシュアップする
- 評価者Bから得た「続けやすさ」「PDF の実用性」の声を、有料機能の設計にも活かす
