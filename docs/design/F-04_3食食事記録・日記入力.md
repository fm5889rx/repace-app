# F-04 3食食事記録・日記入力 — 機能設計書

> 共通事項は [設計書](../設計書.md) を参照。気分・疲労感の数値（F-05）も同じ API（R-03）で保存する。機能名は要件定義書に合わせて「3食」のままとし、間食・飲酒も含めて記録する。

| 項目 | 内容 |
| :--- | :--- |
| 機能ID / 優先度 | F-04 / 必須 |
| 画面 | W-03 メイン画面（記録表） |
| API | R-03 サマリーの保存（表示は R-01） |
| テーブル | daily_summaries（C/R/U） |

## 1. 概要

朝食・昼食・夕食に加え、**間食**（昼食と夕食の間）と**飲酒**（夕食に含める）の内容と、1日の出来事をまとめる日記をテキストで記録する。いずれも任意で、日ごとに保存する。間食をしない人、飲酒をしない人は、その欄を空欄のままにする。

## 2. 画面（W-03 の食事・日記の領域）

食事は時間の順に並べる。

| 順 | 項目 | 種別 | 入力チェック |
| :--- | :--- | :--- | :--- |
| 1 | 朝食 | text | 任意、100文字以内 |
| 2 | 昼食 | text | 任意、100文字以内 |
| 3 | 間食（昼食と夕食の間） | text | 任意、100文字以内 |
| 4 | 夕食 | text | 任意、100文字以内 |
| 4 | └ 飲酒（夕食に含める） | text | 任意、100文字以内（例: ビール500）。夕食の欄の中に並べて表示する |
| — | 日記 | textarea | 任意、**150文字以内**（入力中に残り文字数を表示。上限を超える入力はできない） |

- 飲酒は夕食の一部として扱う。夕食の入力欄の直下に「飲酒」の欄を置き、見た目も夕食のグループにまとめる。
- 食事の5項目（朝食・昼食・間食・夕食・飲酒）は、**1日の合計が120文字以内**。入力中に、5項目の合計の残り文字数を表示する。各項目は100文字以内だが、合計の上限が優先される。
- 間食と飲酒は、使わない人の負担にならないよう、空欄のまま保存でき、強調や警告は出さない。
- 保存のタイミング: 項目の入力を確定（フォーカスが外れる）したときに、その項目だけを R-03 で送る。

### 2.1 スマホの食事欄（間食・飲酒の折りたたみ）

間食をしない人、晩酌をしない人の画面に、使わない入力欄が並ばないようにする（空欄を埋めていないという負担を感じさせない）。スマホ（`md` 未満）だけの仕様で、PC は5項目すべてを常に表示する。

| 項目 | 内容 |
| :--- | :--- |
| 初期表示 | 「朝食」「昼食」「夕食」の3つの入力欄だけを表示する |
| 折りたたみ | 「間食」「飲酒」の入力欄は、初期状態では表示しない（折りたたんでおく） |
| 展開のきっかけ | 夕食の入力欄の下に、「＋ 間食・飲酒を記録する」という文字リンク（またはボタン）を置く。タップすると、その場（インライン）で「間食」「飲酒」の入力欄が展開する。展開した欄は、夕食の入力欄の下に、間食、飲酒の順で並ぶ。展開したあとは、このリンクは表示しない |
| 展開したままにする場合 | その日の間食または飲酒にデータがある（空でない）日は、最初から展開して表示する。また、利用者が展開した日は、その画面を表示している間は展開したままにする（入力を消しても、入力中に欄が消えない） |
| 再表示のとき | 間食・飲酒がどちらも空の日は、再び折りたたんだ状態で表示する |
| 文字数の表示 | 食事の合計の残り文字数（120文字）は、折りたたんでいる間も、間食・飲酒の欄（空）を含めた5項目の合計で数える |
| 印刷との関係 | 画面の折りたたみは W-05 の印刷には影響しない。印刷は従来どおり、朝・昼・間食・夜（飲酒は夜の後ろ）の順で、空欄の項目は出さない（4 章） |

## 3. API

**R-03 サマリーの保存** `PATCH /api/v1/days/{date}/summary`（認証必要、CSRF 必須。F-05 と共通）

```json
// 入力（送った項目だけを更新する。送らなかった項目は変更しない。null は消去を意味する）
{ "breakfast": null, "lunch": "カレースパ", "snack": null, "dinner": "豚しゃぶ", "alcohol": "ビール500", "diary": "午前は集中できた" }
// 出力 200（その日のサマリー全体）
{ "data": { "date": "2026-10-17", "summary": { "morning_mood": 30, "fatigue": 15, "day_mood": 35, "breakfast": null, "lunch": "カレースパ", "snack": null, "dinner": "豚しゃぶ", "alcohol": "ビール500", "diary": "午前は集中できた" } } }
```

| 検証 | 内容 |
| :--- | :--- |
| `breakfast` / `lunch` / `snack` / `dinner` / `alcohol` | 任意、100文字以内（前後の空白を除去し、空なら null） |
| `diary` | 任意、**150文字以内**（生活記録表を A4 横向き1ページに収めるための上限） |
| 食事の合計 | `breakfast`・`lunch`・`snack`・`dinner`・`alcohol` の文字数の合計が **120文字以内**。R-03 は一部の項目だけ送るため、保存済みの項目と合わせた結果で検証する。超える場合は 422（「食事（朝食・昼食・間食・夕食・飲酒）の合計は120文字以内で入力してください。」） |

| ステータス | 条件 |
| :--- | :--- |
| 401 | 未ログイン |
| 419 | CSRF トークン不一致 |
| 409 | その日の週が確定済み（F-11） |
| 422 | 入力エラー（長すぎる、日付が不正） |

## 4. データ

- `daily_summaries`: (user_id, record_date) で1行。無ければ作成、あれば送られた項目だけ更新する（UPSERT）。すべての項目が null になった行は残してよい。
- 食事の項目: `breakfast`、`lunch`、`snack`（間食）、`dinner`、`alcohol`（飲酒。夕食に含めて扱う）。いずれも varchar(100)、NULL 可。
- 表示は R-01 で、週の日付範囲の行をまとめて取得する。
- 印刷（W-05）では、朝・昼・間食・夜（飲酒は夜の後ろ）の順に1行へ並べ、空欄の項目は出さない。日記と食事が多くて1ページに収まらない場合に限り、日記・食事記録エリア全体の文字サイズを段階的に下げる（F-07）。

## 5. 振る舞い

- 保存の流れは F-03 と同じ（検証→UPSERT→200）。トランザクションは1文なので不要。
- 失敗時は入力を残して再試行できる。日記が長い場合に備え、保存前の内容を画面に保持する。

## 6. 受け入れ条件とテスト観点

| 受け入れ条件 | 観点 |
| :--- | :--- |
| 朝食・昼食・夕食・日記を保存すると、再表示で同じ内容が出る | 正常: R-03 の後に R-01 で同じ内容 |
| 間食を入力すると、昼食と夕食の間の項目として保存・表示される | 正常: `snack` が保存され R-01 で返る |
| 飲酒を入力すると、夕食の一部として保存・表示される | 正常: `alcohol` が保存され、W-03 で夕食のグループに表示される |
| 間食・飲酒を入力しなくても保存できる | 正常: 間食なし・飲酒なし、間食あり・飲酒なし、間食なし・飲酒ありの3パターン |
| 一部の項目だけ送っても、他の項目は変わらない | 正常: 朝食のみ送信して昼食・間食・夕食・飲酒・日記・数値が保たれる |
| 空にして保存すると、その項目が消える | 正常: null を送ると null |
| 長すぎる入力は保存されず、エラーが出る | 異常: 食事・間食・飲酒が101文字、日記151文字、食事の合計が121文字（保存済みの項目と合わせて超える場合を含む） |
| 境界の文字数は保存できる | 境界: 食事・間食・飲酒が100文字、日記150文字、食事の合計が120文字ちょうど |
| 他人のデータには影響しない | 異常: 他の利用者の同じ日付の行が変わらない |
| スマホで、初期表示は朝食・昼食・夕食の3欄だけになる | 手動確認（間食・飲酒の欄は出ない） |
| 「＋ 間食・飲酒を記録する」をタップすると、夕食の下に間食・飲酒の欄がその場で展開する | 手動確認（展開後はリンクが消える） |
| 間食または飲酒にデータがある日は、最初から展開して表示される | 正常: 間食だけ、飲酒だけ、両方ありの日。手動確認 |
| 間食・飲酒がどちらも空の日は、折りたたんで表示される | 正常: 手動確認 |
| 展開した日は、入力を消しても欄が消えない | 境界: 間食を入力して消す。手動確認 |
| PC は5項目が常に表示される | 手動確認 |
