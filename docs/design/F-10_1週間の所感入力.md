# F-10 1週間の所感入力 — 機能設計書

> 共通事項（週の開始日の求め方は [F-09](F-09_週開始曜日設定.md)）は [設計書](../設計書.md) を参照。

| 項目 | 内容 |
| :--- | :--- |
| 機能ID / 優先度 | F-10 / 必須 |
| 画面 | W-03 メイン画面（最下部）、W-05（表示のみ） |
| API | R-04 `PUT /api/v1/weeks/{start_date}/notes`（表示は R-01） |
| テーブル | weeks（C/R/U） |

## 1. 概要

週末に、その週全体の振り返りとして「今週の目標」と「今週の所感」を自由に書いて保存する。W-05 の最下部にも反映される。

## 2. 画面（W-03 の週の記入欄）

| 項目 | 種別 | 入力チェック |
| :--- | :--- | :--- |
| 今週の目標 | text | 任意、**80文字以内**（残り文字数を表示。原紙の1行の枠に合わせる） |
| 今週の所感 | textarea | 任意、**250文字以内**（残り文字数を表示。原紙の2行の枠に合わせ、印刷では文字サイズの自動縮小の対象。F-07） |

- スマホでは画面の最下部、PC では記録表の下部に置く。
- 保存のタイミング: 入力を確定（フォーカスが外れる）したときに送る。

## 3. API

**R-04 週の目標・所感の保存** `PUT /api/v1/weeks/{start_date}/notes`（認証必要、CSRF 必須）

```json
// 入力（2項目をこの内容で置き換える。未入力は null）
{ "weekly_goal": "朝7時に起きる", "weekly_reflection": null }
// 出力 200
{ "data": { "start_date": "2026-11-02", "weekly_goal": "朝7時に起きる", "weekly_reflection": null } }
```

| 検証 | 内容 |
| :--- | :--- |
| `{start_date}` | `YYYY-MM-DD` の日付で、その日付を含む週の開始日（週開始曜日の履歴から計算。設計書 5.2）に一致すること |
| `weekly_goal` | 任意（null 可）、**80文字以内**（前後の空白を除去し、空なら null） |
| `weekly_reflection` | 任意（null 可）、**250文字以内**（前後の空白を除去し、空なら null） |

| ステータス | 条件 |
| :--- | :--- |
| 401 | 未ログイン |
| 419 | CSRF トークン不一致 |
| 422 | 週開始と一致しない日付、1001文字以上、日付形式が不正 |

## 4. データ

- `weeks`: (user_id, start_date) で1行。無ければ作成、あれば置き換える（UPSERT）。2項目とも null になった行は残してよい。
- 表示は R-01 の `weekly_goal` / `weekly_reflection`。

## 5. 振る舞い

- 保存の流れは F-04 と同じ（検証→UPSERT→200）。
- 週の開始曜日を変更しても、過去の週は当時の開始曜日のまま維持される（F-09）。そのため、`weeks` の `start_date` が週の区切りとずれることはない。

## 6. 受け入れ条件とテスト観点

| 受け入れ条件 | 観点 |
| :--- | :--- |
| 目標と所感を保存すると、その週を再表示したときに出る | 正常: R-04 の後に R-01 で同じ内容 |
| 別の週には出ない | 正常: 前週・翌週は空 |
| W-05 の最下部に反映される | 正常: 手動確認 |
| 週開始と一致しない日付では保存できない | 異常: 週の途中の日付で 422 |
| 長すぎる入力は拒否される | 異常: 目標81文字、所感251文字 |
| 境界の文字数が通る | 境界: 目標80文字ちょうど、所感250文字ちょうど |
| 他人のデータには影響しない | 異常: 他の利用者の同じ週の行が変わらない |
