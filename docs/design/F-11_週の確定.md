# F-11 週の確定（所感を保存して週を完成） — 機能設計書

> 共通事項は [設計書](../設計書.md) を参照。目標・所感は [F-10](F-10_1週間の所感入力.md)、週の求め方は [F-09](F-09_週開始曜日設定.md)。

| 項目 | 内容 |
| :--- | :--- |
| 機能ID / 優先度 | F-11 / 必須 |
| 画面 | W-03・W-06 メイン画面（確定ボタン、確定後は読み取り専用）、W-05（確定した週も再プレビュー・再印刷できる） |
| API | R-07 `POST /api/v1/weeks/{start_date}/confirm`（確定状態は R-01 の `is_confirmed`）、R-02・R-03・R-04・R-06（確定済みの週への書き込みは 409） |
| テーブル | weeks（C/R/U。`is_confirmed`、`confirmed_at`） |

## 1. 概要

**時間による締め切りは設けない。** 利用者は、最終日の睡眠・サマリーや週の所感を翌日以降（次の週に入った後）に書くことがあるため、前の週のデータを、確定するまでいつでも入力・編集できる。

週の終わりまたは週明けに、利用者が「今週の所感」（250文字以内）を入力して **【所感を保存してこの週を完成させる】** ボタンを押したときが「週の確定」になる。確定すると、その週に属する行動記録、日次サマリー、週次データ（目標・所感）がすべて**読み取り専用（ロック）**になり、閲覧と、再プレビュー・再印刷（W-05、F-07・F-08）だけができる。確定の取り消しはできない。

- 要件定義書 7「過去データの再入力・編集機能」のスコープ外とした範囲は、この確定した週とする。
- 確定の状態は `weeks.is_confirmed` で管理する。

## 2. 画面（W-03・W-06）

| 項目 | 内容 |
| :--- | :--- |
| 「所感を保存してこの週を完成させる」ボタン | 今週の所感の欄の下に置く（スマホでは、どの日の画面でも最下部の同じ位置）。所感が空の間は非活性。押すと確認ダイアログ「この週を完成させます。完成すると、この週の記録は変更できなくなります（表示と印刷はできます）。よろしいですか？」を出し、「完成させる」「やめる」を選ぶ |
| 確定後の表示 | 「完成済み（YYYY/MM/DD）」の文字表示（色だけに頼らない）。行動・食事・日記・気分・疲労感・目標・所感の入力欄を非活性（読み取り専用）にし、区間の追加・削除や日の削除のボタンも出さない |
| 完了メッセージ | 「この週を完成させました」 |
| 印刷 | 確定した週も W-05 で再プレビュー・再印刷（PDF保存）できる |

- 確定していない週は、過去の週でも、次の週に入った後でも、通常どおり入力・編集できる。
- 所感の欄は、通常の保存（F-10。入力を確定したときに保存）も使える。ボタンは「保存＋確定」を1回で行う。

## 3. API

**R-07 週の確定** `POST /api/v1/weeks/{start_date}/confirm`（認証必要、CSRF 必須）

```json
// 入力（所感を保存し、その週を確定する。目標は任意）
{ "weekly_goal": "朝7時に起きる", "weekly_reflection": "早起きは3日できた。来週は夜更かしを減らす。" }
// 出力 200
{ "data": { "start_date": "2026-11-02", "weekly_goal": "朝7時に起きる", "weekly_reflection": "早起きは3日できた。来週は夜更かしを減らす。", "is_confirmed": true, "confirmed_at": "2026-11-09T08:30:00+09:00" } }
```

| 検証 | 内容 |
| :--- | :--- |
| `{start_date}` | `YYYY-MM-DD` の日付で、その日付を含む週の開始日に一致すること（F-10 と同じ）。今日（Asia/Tokyo）より後に始まる週は確定できない |
| `weekly_reflection` | **必須**、250文字以内（前後の空白を除去し、空は不可） |
| `weekly_goal` | 任意（null 可）、80文字以内 |
| 確定の状態 | まだ確定されていないこと |

| ステータス | 条件 |
| :--- | :--- |
| 401 | 未ログイン |
| 409 | すでに確定済み。「この週はすでに完成しています。」 |
| 419 | CSRF トークン不一致 |
| 422 | 所感が空・251文字以上、目標が81文字以上、週開始と一致しない日付、まだ始まっていない週 |

**確定済みの週への書き込み**: 確定済みの週に対する R-02（日またぎの翌日分を含む）、R-03、R-04、R-06 は **409** を返し、変更しない。「この週は完成済みのため、変更できません。閲覧と印刷のみできます。」日をまたぐ保存で、どちらかの日が確定済みの週に入る場合は、2日分とも保存しない（F-03 のトランザクション）。P-01・P-02（行動の選択肢）は週に属さないため対象外。

## 4. データ

- `weeks.is_confirmed`（boolean、既定 false）と `weeks.confirmed_at`（datetime、NULL 可）。確定時に true と現在時刻を入れる。false に戻す API はない。
- R-07 は、トランザクションで `weeks` の行を取得（なければ作成、行ロック）→ 検証 → 目標・所感を保存し `is_confirmed`=true、`confirmed_at` を設定する。二重に押されても1回だけ確定する（2回目は 409）。
- 書き込み系 API は、対象の日が属する週（週開始曜日の履歴から計算）の `weeks` 行の `is_confirmed` を確認する。行がない週は未確定として扱う。
- 確定の状態は R-01 の `is_confirmed`・`confirmed_at` で返す。

## 5. 週をまたぐ睡眠時間の計算

- 睡眠時間は保存せず、`is_sleep` の区間（15分単位）から、取得のたびに計算する（仕様チェックリスト項目Q-06、設計書 4.2）。
- 日をまたぐ睡眠（例: 旧週の最終日 23:00〜新週の初日 6:00）は、日ごとに分割して保存する。旧週の最終日には 23:00〜24:00 の1時間、新週の初日には 0:00〜6:00 の6時間が、それぞれの日付のレコードに保存される。
- **睡眠時間は、起きた日に全体を数える。** 上の例では、新週の初日の睡眠時間が7.0で、旧週の最終日は0。新週の最初の日を計算するときは、前の週の最終日の夜の区間を読む。**週をまたぐ集計が必要。**
- そのため R-01 は、週の前日と翌日の区間も読んで各日の `sleep_hours` を計算する。ただし、返す `days` は週の日数分だけで、前の週・次の週の日は含めない。
- 旧週の最終日の夜（23:00〜24:00）を書き込むには、旧週が確定前である必要がある。旧週を確定した後は、その日を編集できないため、新週から旧週の最終日の夜を含む睡眠を保存しようとすると 409 になる（2日分とも保存されない）。**旧週は、最終日の夜の睡眠を入力してから確定する。**

## 6. 受け入れ条件とテスト観点

| 受け入れ条件 | 観点 |
| :--- | :--- |
| 所感を入力して「この週を完成させる」を押すと、確認のあと週が確定し、入力欄が読み取り専用になる | 正常: R-07 の 200 の後、R-01 の `is_confirmed` が true（Claude in Chrome で画面も確認） |
| 所感が空では確定できない | 異常: ボタンが非活性。R-07 で 422 |
| 次の週に入った後でも、確定前の週は編集できる | 正常: 翌週の日付でも、前の週の日の R-02 が 200 |
| 確定済みの週は変更できない | 異常: R-02・R-03・R-04・R-06 が 409。DB の値が変わらない |
| 日またぎ保存で、どちらかが確定済みの週なら、2日分とも保存されない | 異常: R-02 が 409、当日分も保存されていない |
| 確定済みの週を再度確定すると拒否される | 異常: R-07 で 409 |
| 確定した週も、表示・再プレビュー・再印刷ができる | 正常: R-01 が 200、W-05 が表示でき、印刷できる |
| 確定の取り消しはできない | 正常: 取り消しの API と操作がない |
| まだ始まっていない週は確定できない | 異常: 未来の週の `start_date` で 422 |
| 週をまたぐ睡眠が、起きた日（新週の初日）に全体で数えられる | 正常: 日曜 23:00〜24:00 と月曜 0:00〜6:00 で、月曜が 7.0、日曜が 0 |
| 旧週の確定後は、旧週の最終日の夜を含む睡眠を保存できない | 異常: 日曜の週を確定後、月曜から 23:00 の睡眠を保存すると 409。月曜の区間も保存されない |
| 旧週の最終日の夜を入力してから確定すれば、新週の初日に正しく出る | 正常: 日曜 23:00〜24:00 を入力して確定した後でも、R-01 の月曜が 7.0 |
| 他人の週は確定できず、影響もしない | 異常: 他の利用者の同じ週の `is_confirmed` が変わらない |
| 週開始と一致しない日付では確定できない | 異常: 週の途中の日付で 422 |
