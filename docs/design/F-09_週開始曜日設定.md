# F-09 週開始曜日設定 — 機能設計書

> 共通事項は [設計書](../設計書.md) を参照。

| 項目 | 内容 |
| :--- | :--- |
| 機能ID / 優先度 | F-09 / 優先 |
| 画面 | W-04 設定画面（`/settings`） |
| API | S-01 `PATCH /api/v1/user/settings`、A-04 `GET /api/v1/user` |
| テーブル | week_start_settings（C/R/U/D）、weeks・daily_summaries・activity_segments（R。最新の記録日の検索） |

## 1. 概要

週の開始曜日は人によって異なる（月曜、土曜、日曜（カレンダーと同じ）など）。**既定は月曜始まり**（多数の利用者の利便性のため）とし、設定画面で **カレンダーから「週の開始日」を選ぶと、その日の曜日が開始曜日になる**。たとえば 11/7（土）を選ぶと、11/7 以降の新しい週から、毎週土曜日が週の始まりになる。

- **すでに記録がある週は、当時の開始曜日のまま維持する。** 変更は、選んだ日以降の新しく作られる週から適用する。
- 変則週や欠損期間を示すための専用のフラグや列は設けない。週の区切りは、設定の履歴（`week_start_settings`）から計算する（設計書 5.2）。
- 選べる日付は、**まだ確定していない現在進行中の最新の週の初日（P）以降のみ**。[F-11](F-11_週の確定.md) で確定した週（完成済みの週）に属する日付は選べない。P は、今日（日本時間）を含む週が未確定ならその週の開始日、確定済みならその週の終了日の翌日。
- 選んだ日付は、設定の「有効開始日」（`effective_from`）として保存する。
- 曜日を直接選ぶ欄は設けない（カレンダーで選ぶ方式に一本化する）。

## 2. 画面（W-04）

| 項目 | 種別 | 入力チェック |
| :--- | :--- | :--- |
| 週の開始日 | カレンダー（日付の選択） | 必須、有効な日付。**P（まだ確定していない現在進行中の最新の週の初日）以降の日付のみ選べる**（確定済みの週に属する日付は選べない。F-11） |

- 現在の設定を「現在: 毎週月曜日が週の始まりです」の形式で表示する。切り替えが予定されている場合は、「11/7（土）から、毎週土曜日が週の始まりになります」も表示する。
- カレンダーで日付を選ぶと、画面に即時にプレビューを出す（サーバーには送らない）。
  - 「選んだ日: 2026/11/7（土）→ この日以降は、毎週土曜日が週の始まりになります」
  - 「すでに記録がある週は、今までの開始曜日のままです」
- カレンダーでは、P より前の日付を選べないようにする（無効表示）。P は A-04 の `week_start_selectable_from` で取得する。
- 操作: 「保存」ボタン、W-03 への戻りリンク、ログアウトボタン。
- 保存に成功したら「保存しました」を表示し、W-03 に戻ると、切り替え日以降の週が新しい区切りで表示される。
- 選択エラーのときは、保存せず、カレンダーの下にエラーを表示する（内容は 3 章）。選んだ日付はそのまま残す。

## 3. API

**S-01 週開始曜日の設定** `PATCH /api/v1/user/settings`（認証必要、CSRF 必須）

```json
// 入力（カレンダーで選んだ日付。この日以降の週に、その曜日を適用する）
{ "week_start_date": "2026-11-07" }
// 出力 200
{ "data": { "week_start_day": 6, "effective_from": "2026-11-07" } }
```

| 検証 | 内容 |
| :--- | :--- |
| `week_start_date` | 必須、`YYYY-MM-DD` として存在する日付、2000-01-01〜2100-12-31 |
| 確定済みの週との関係 | P 以降の日付であること。P は、今日（Asia/Tokyo）を含む週が未確定ならその週の開始日、確定済みならその週の終了日の翌日。P より前は、確定済みの週に属するため選べない（F-11） |

| ステータス | 条件 |
| :--- | :--- |
| 401 | 未ログイン |
| 419 | CSRF トークン不一致 |
| 422 | 日付が空、形式が不正、存在しない日付（例 2026-02-30）、範囲外 |
| 422 | P（まだ確定していない現在進行中の最新の週の初日）より前の日付を選んだ |

```json
// 422（P より前を選んだ場合）
{
  "message": "週の開始日は、まだ確定していない現在進行中の週の初日（2026-11-09）以降の日付を選んでください。完成済みの週は変更できません。",
  "errors": { "week_start_date": ["週の開始日は、まだ確定していない現在進行中の週の初日（2026-11-09）以降の日付を選んでください。完成済みの週は変更できません。"] },
  "code": "week_start_locked",
  "details": { "selectable_from": "2026-11-09" }
}
```

- A-04 の `week_start_day` は、**今日に有効な設定**の開始曜日を返す。あわせて `week_start_selectable_from`（P）を返す。

## 4. データ

`week_start_settings`（利用者ごとの設定の履歴。`week_start_day` 0=日〜6=土、`effective_from` 有効開始日。設計書 4.2）。

**最新の記録日（L）**: `daily_summaries.record_date`・`activity_segments.record_date` の最大値と、`weeks.start_date` の最大値（週の開始日）を調べ、最も新しい日を L とする（3回の最大値の取得。いずれも利用者と日付の索引を使う）。いずれにも記録がなければ「記録なし」。

**保存の手順**

1. 検証（上の表）。
2. 記録がない場合: 登録時の行（`effective_from`=2000-01-01）の `week_start_day` を、選んだ日の曜日に書き換える（全期間に適用する。過去に記録がないため影響がない）。
3. 記録がある場合:
   - 選んだ日（D）に有効な設定の曜日と、D の曜日が同じなら、何もしない（200 を返す）。
   - 異なる場合は、`effective_from` が L より後の既存の行（予約済みで、まだ記録に影響しない設定）を削除し、`effective_from`=D、`week_start_day`=D の曜日の行を追加する。
4. 過去の週（`effective_from` が D より前の期間）は、当時の設定のまま計算される。

**週の求め方**（設計書 5.2）: 日付 X を含む週は、X に有効な設定（`effective_from` ≦ X の最大の行）の曜日 w と `effective_from` f から、`開始日 = max(X − ((X の曜日 − w + 7) % 7), f)`、`終了日 = min(開始日 + 6, 次の設定の f − 1)` で求める。切り替え前の最後の週だけが、切り替え日の前日までの日数（1〜7日）になる。

- 既存の `activity_segments`・`daily_summaries` は日付に紐づくため影響を受けない。`weeks`（目標・所感）は保存時の `start_date` のまま維持され、過去の週と一致する。

## 5. 振る舞い

- 曜日の決定は、サーバーが日付の曜日から行う（画面のプレビューと一致させるため、フロントも同じ計算でプレビューする）。
- P の検査は、サーバー側で必ず行う（フロントは P より前を無効表示にするが、検証は必須）。最新の記録日（L）は、保存の手順で「記録がない」場合かどうかの判定にだけ使う。
- 保存したら、画面の利用者情報（A-04 の内容）を更新する。W-03 は、切り替え日以降の週から新しい区切りで表示される。
- 切り替え前の最後の週は7日未満になる。W-03・W-05・グラフは、その週の日数分だけを表示する（空の日を作らない）。
- 失敗した場合は、選択した日付を保持してエラーを表示する。

## 6. 受け入れ条件とテスト観点

| 受け入れ条件 | 観点 |
| :--- | :--- |
| 新規登録の直後は、週が月曜始まりになっている | 正常: `week_start_day`=1、A-04 が 1 |
| 記録がない利用者が日付を選ぶと、全期間でその曜日が開始曜日になる | 正常: 記録なしで 2026-11-07（土）→ 6。過去の週も土曜始まり |
| 記録がある利用者が、P 以降の日付を選ぶと、その日以降の週から新しい開始曜日になる | 正常: 今日が 11/3（週は 11/2〜、未確定）で、2026-11-07（土）を選ぶ → 11/7 以降が土曜始まり |
| すでに記録がある週の区切りは変わらない | 正常: 変更前後で、10/19〜10/25 の週の `start_date`・`end_date`・記録が同じ |
| 切り替え前の最後の週が、切り替え日の前日までになる | 境界: 月曜始まりの 10/26〜11/1 の週が、11/7 切り替えで 11/2〜11/6（5日）になる |
| 切り替え日以降の週は7日で、新しい曜日から始まる | 正常: 11/7〜11/13 |
| 確定済みの週の日付は選べず、エラーになる | 異常: 11/2〜11/8 の週を確定したあと 11/5 を選ぶ → 422 `week_start_locked`、設定は変わらない |
| 未確定の現在進行中の週の初日は選べる、確定済みなら翌日から | 境界: 未確定で P=11/2 のとき 11/1 は 422、11/2 は 200。11/2〜11/8 の週を確定した後は P=11/9 で、11/8 は 422、11/9 は 200 |
| カレンダーで、P より前の日付が選べない表示になる | 手動確認 |
| 同じ曜日が有効な日を選んでも、設定は増えない | 正常: 月曜始まりのまま月曜を選ぶ → 200、行が増えない |
| 予約済みの設定を、別の日付で上書きできる | 正常: 11/7（土）を予約後に 11/14（日）を選ぶ → 11/7 の行が削除され、11/14 の行だけが残る |
| 不正な日付は拒否される | 異常: 空、`abc`、2026-02-30、1999-12-31、2101-01-01 |
| 境界の日付が通る（記録なし） | 境界: 2000-01-01、2100-12-31 |
| 直近の記録は、日次サマリー・行動の区間・週の目標のどれから見ても検査される | 境界: 3つの表それぞれにだけ記録がある場合、未来の日付の記録がある場合 |
| 他人の記録・設定は影響しない | 異常: 他の利用者に記録があっても、自分に記録がなければ全期間に適用できる |
| 週の求め方が正しい | 自動: 7通りの曜日、設定が複数ある履歴、切り替え日の前後の日付 |
| 設定が再ログイン後も保持される | 正常: A-04 の `week_start_day` が保存値 |
| 保存に失敗しても入力データが変わらない | 正常: エラー時、行動の区間・サマリー・週の目標が変更前と同じ |
